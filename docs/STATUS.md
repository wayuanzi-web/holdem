# 德州軍師 現況盤點

這份文件是讀完整個 repo 後寫的（只讀程式、沒有改任何程式）。

## 一、功能清單（玩家看得到的）

**牌局（首頁）**
- 跟電腦打無限注德州撲克，2–9 人桌，每人 200 籌碼（100 大盲）
- 電腦對手四種強度（新手、普通、高手、GTO）與多種風格（tag、lag、rock、station、maniac、gto）
- 一般桌、錦標賽（盲注依手數升級、打到剩一人）、GTO 訓練（單挑）三種玩法
- 自動出牌（輪到你才停）與逐步模式（每件事按「下一步」）、出牌速度四段（慢、中、快、超快；牌桌上也能換）；超快時你棄牌就直接跳到這一手結束，停在結果由你決定要不要再來一手
- 全下放在「加注…」打開的框裡（要再按「確定全下」）；動作鈕剛出現的 0.45 秒點不到，避免連按「跳到輪到你」誤按
- 上一步／下一步，可回頭重看
- 教練：每一步的解說、輪到你時的建議與原因、按完後的評分
- 教練「詳細解說」：底池賠率、勝率怎麼算、為什麼打折，用這一手的實際數字講
- 「偷看」對手的牌（開關）
- 一手結束的逐步檢討：每個決定當時猜的範圍、對手實際的牌、你對在哪錯在哪
- 單挑轉牌、河牌的牌局內 GTO：顯示每個動作的 EV、按完用 GTO 評分、GTO 電腦照解打
- 邊池、最小加注、全下等規則完整處理
- 首頁累計數字（手數、輸贏、勝場）
- 個人統計（VPIP、PFR、攤牌率、位置、進攻性等），一般桌／錦標賽／GTO 訓練分開記
- 深入說明開關（名詞、勝率怎麼算）

**大師之路（課程）**
- 8 階 45 課：基礎、起手牌五層、翻牌前進攻、翻牌前防守、數學、翻牌後基礎、範圍思維、GTO
- 題目由程式產生（無限題、答案由引擎算）
- 分級測驗與跳級、快答訓練場、起手牌字典、陷阱牌專題
- 實戰考核：牌桌發設計好的牌，教練先不說話，按完評分
- GTO 訓練場、畢業考、結業證書
- 做過的題目歷史紀錄（回頭看解釋、再抽題重考）

**工具分頁**
- 勝率計算機：手牌＋公牌對 1–N 家的勝率、牌型機率、出牌數（Outs）
- 範圍對範圍勝率（勝率計算機第二模式）
- 翻牌前圖表：開牌、面對加注、面對 3-bet、面對 4-bet；7–9 人、3–6 人、單挑三套；可編輯、存檔
- 範圍透視：對手範圍（廢牌拿掉後剩什麼）、你的牌對它的勝率、公牌與動作如何縮小範圍
- GTO 工作室：設定局面、Discounted CFR 求解、看策略／EV、範圍編輯器、範圍庫、分享連結、從牌局帶入
- 工作室的多翻牌報告（同一組範圍套到很多翻牌）
- 多執行緒分工求解、速度設定、壓縮記憶體選項
- 效能測試（量評牌、勝率、求解速度）

**網頁 App 專屬**
- 分享按鈕、安裝到主畫面（含 iOS 說明、LINE 等內建瀏覽器改用外部瀏覽器）
- 離線快取（Service Worker）

資料都存在本機 localStorage，沒有後端。

## 三、測試清單（test/）

`run-all.sh` 依序跑下列項目。

- `engine.js`：不是測試，是載入器，把 src/engine 串起來給其他測試用
- `eval-exhaustive.js`：評牌器全列舉（5 張 259 萬手、7 張 1.3 億手的牌型次數、7462 種不同值）
- `eval-treys.js` ＋ `py/treys_dump.py`：隨機 20 萬手 7 張牌，大小順序跟 treys 一致
- `equity-check.js`：勝率、牌型機率、出牌數對照 treys 算的數字
- `solver-toy.js`：解析解對照（IP 詐唬頻率、OOP 跟注頻率符合理論）
- `solver-dump.js` ＋ `py/br_check.py`：河牌、轉牌局面，Python 獨立重算最佳反應值與 EV，跟 JS 比
- `game-cases.js`：牌局規則的指定情境
- `game-random.js`：亂下兩萬手，檢查籌碼守恆、邊池、贏家正確、最小加注
- `ai-sim.js`：電腦對電腦打多手，看各風格數字與決策耗時、確認每手都會結束
- `coach-sim.js`：照教練建議打多手，檢查解說、建議、評分不出錯
- `studio.js`：從牌局帶入工作室、範圍大小、樹、求解、照實際打法走、下一張牌報告、牌型分類
- `solver-iso.js`：花色同構與壓縮的結果要跟不用時一樣
- `solver-par.js`：分工求解要跟單人求解一樣
- `par-threads.js`：真的開 worker_threads 跑分工求解
- `gto-game.js`：牌局內 GTO（建局面、對到樹上、河牌接轉牌的解）
- `charts.js`：翻牌前圖表可解析、2–9 人各座位都查得到合理情況、推或棄
- `rvr.js`：範圍對範圍跟暴力列舉一致、空範圍不壞
- `tourney.js`：錦標賽籌碼守恆、名次連續、盲注升級、單挑不連下兩次大盲
- `batch.js`：多翻牌報告的權重、分類、彙整
- `learn.js`：每種題目只有一個正確答案且與引擎一致；課表、分級、進度、字典資料
- `bench.js`：不在 run-all 內，在 Node 跑效能測試給手機數字當參考

## 四、問題與可改進處（依重要性）

1. **畫面層（src/parts，約 4000 行）完全沒有自動化測試**：test/ 只測引擎，按鈕、存檔讀取、分頁、離線快取壞了不會被發現。可考慮加一個用 jsdom 或無頭瀏覽器的冒煙測試（會牽涉新套件，需要你決定）。
2. **沒有 CI**：沒有 `.github/workflows`，測試只靠人手動跑；main 一推就上線，沒有任何擋關。可加一個 PR 時自動跑 `run-all.sh` 與檢查建置產物是否同步的工作流程（需要你決定）。
3. **建置產物是否同步沒有自動檢查**：`index.html` 約 800 KB 與 `sw.js` 要手動重建，忘了就會上線舊版。實測重建後 index.html 與 repo 內一致，sw.js 每次建置都會變（含版本戳記），所以檢查要排除它。
4. **測試跑約 3 分鐘，且依賴 pip 套件 treys**：沒有 requirements 檔或 README 說明，新環境容易卡住；README 的測試說明也沒列出後半段（求解、圖表、錦標賽、課程）。
5. **小的文件落差**：`55-studio.js` 開頭註解寫「46-studio」（檔名已改）；README 的檔案說明沒提 `70`–`76` 的課程與範圍透視模組。
